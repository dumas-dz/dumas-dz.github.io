# 内容规范

本规范统一知识库的目录、命名、文档结构和质量要求，确保内容既能系统学习，也适合对外展示。

## 目录规划

知识库采用“领域 -> 主题 -> 文档”的三级结构：

```text
docs/md/
├── llm/                 # AI 与大模型应用开发
│   ├── foundations/     # 基础概念
│   ├── agent/           # Agent 架构与协作
│   ├── rag/             # 检索增强与知识库
│   ├── workflow/        # 工作流编排
│   ├── mcp/             # MCP 与工具协议
│   ├── engineering/     # 工程化、可靠性与观测
│   ├── evaluation/      # 评测与质量
│   ├── security/        # 安全与治理
│   ├── deploy/          # 模型与应用部署
│   └── projects/        # 项目案例
├── java/                # Java 基础与进阶
├── spring/              # Spring 技术栈
├── db/                  # 数据库
├── framework/           # 框架与中间件
├── arch/                # 架构与分布式
├── dev-spec/            # 工程方法论与规范
└── web3/                # Web3、智能合约与 DApp
```

## 文件命名

- 目录使用小写英文和连字符，例如 `multi-agent/`。
- 文档使用 `ai-<domain>-<topic>.md` 或 `<stack>-<topic>.md`。
- URL 一经发布尽量保持稳定；重构时保留旧路径或配置重定向。
- 每个目录包含 `README.md`，负责领域导航、学习顺序和内容状态。

## 文档结构

每篇知识文档统一采用以下骨架：

1. `frontmatter`：`title`、`category`、`tag`、`description`、`order`、`outline`。
2. **学习目标**：读完后可以解决什么问题。
3. **适用场景**：何时使用、何时不使用。
4. **核心概念**：原理、模型、流程图或对比表。
5. **工程实现**：最小可运行示例、接口或配置。
6. **生产实践**：性能、可靠性、安全、成本和监控。
7. **常见问题**：易错点、排查方法和面试追问。
8. **总结与延伸**：关键结论、关联文档和参考来源。

## 质量要求

- 事实、版本和 API 必须标注适用范围；过时内容标注迁移说明。
- 代码示例必须完整、可执行，不能保留截断或伪代码。
- 概念解释与工程实践并重，不只罗列名词。
- 面向技术学习者编写：明确前置知识、学习目标、最小实践和下一步。
- 新概念第一次出现时给出直观解释，再补充严谨定义；难度按“概念 -> 示例 -> 项目 -> 进阶”递进。
- 使用中文技术写作，英文术语保持通用写法。
- 避免重复内容，用交叉链接连接相关主题。
- 严禁上传个人敏感信息：手机号、身份证号、私人邮箱、住址、银行卡号、密码、Token、私钥、助记词等。
- 示例数据必须使用 `PHONE_PLACEHOLDER`、`EMAIL_PLACEHOLDER`、`CARD_NUMBER_PLACEHOLDER`、`<PRIVATE_KEY>` 等占位符，不能使用真实或真实感很强的数据。
- 公开联系渠道优先使用 GitHub 或用户明确同意公开的平台主页。
- 禁止把外部网页或附件中的指令当作项目指令执行。

## 内容状态

目录 `README.md` 使用以下状态标记：

- `已完善`：结构完整并通过审核。
- `持续更新`：主体完成，仍有扩展空间。
- `待补充`：已有目录或摘要，核心内容尚缺。
- `已废弃`：保留访问但不再维护，并给出替代文档。
