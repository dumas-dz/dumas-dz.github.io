## 项目背景

CRM 对外服务需要向不同交易所生成代销统计报告。不同交易所在字段、模板、口径、生成时间、文件格式和上报规则上存在差异，如果在业务代码中逐个复制报表逻辑，会带来以下问题：

- 新增交易所时修改点分散，开发和回归成本高。
- 多个报告并行处理时容易出现资源竞争和任务重复。
- Excel 模板差异大，统计口径不一致会影响报表可读性和准确性。

项目目标是把报表生成抽象为可配置、可扩展的组件，用统一调度和缓存机制处理高频统计任务。

## 职责范围

我作为核心开发，负责：

- 负责三方销售报表统计与上报模块设计。
- 基于策略模式封装交易所差异化报告逻辑。
- 集成 PowerJob 分布式调度与 Redis 异步缓存。
- 使用 EasyExcel 完成 30+ 种 Excel 报告生成。
- 参与 Oracle 数据访问、统计口径和异常重跑设计。

## 技术方案

### 策略模式拆分差异

将“报告公共流程”和“交易所差异逻辑”拆开：

```text
报表任务调度
  -> 报告类型与交易所路由
  -> ReportStrategy
     -> 数据查询
     -> 口径计算
     -> 模板适配
     -> 文件生成
  -> 结果缓存 / 上传 / 上报
```

公共流程负责任务、参数、日志、异常和生命周期管理；策略实现负责不同交易所的字段映射、统计口径和模板差异。新增交易所时，优先新增策略实现，而不是修改已有报表流程。

### 分布式调度与性能优化

- 使用 PowerJob 承担分布式任务调度和执行管理。
- 使用 Redis 异步缓存支撑热点数据和结果复用。
- 将可并行的数据查询、统计和文件生成拆分处理，减少单个长任务对整体报告周期的影响。

### Excel 报告生成

基于 EasyExcel 统一处理模板、样式、字段填充和文件导出，降低直接操作 Excel 对业务逻辑的侵入。对于复杂报告，优先保证数据口径、字段顺序和错误提示的清晰性。

### 关键技术栈

`Spring Boot 3`、`MyBatis-Plus`、`Oracle`、`PowerJob`、`Sa-Token`、`EasyExcel`。

## 项目成果

- 基于策略模式封装 30+ 交易所差异化报告逻辑，支持 16+ 家交易所报表生成。
- 据项目记录，新增交易所的开发周期缩短 70%。
- 通过 PowerJob 分布式调度与 Redis 异步缓存进行并行处理和性能优化。
- 据项目记录，报告生成时间缩短 30%。

## 反思与改进

- **报表系统的核心是口径治理**：模板和字段差异容易处理，统计口径、时间窗口、失败重跑和审计记录更需要统一规范。
- **策略模式要配套清晰契约**：输入、输出、异常和校验规则明确后，策略替换才不会把问题转移到调用方。
- **性能优化需要可观测数据**：并行、缓存和任务拆分必须结合任务耗时、失败率和资源占用验证。
- **Excel 是交付格式，不是数据模型**：底层应先稳定数据结构和统计结果，再适配不同模板。
