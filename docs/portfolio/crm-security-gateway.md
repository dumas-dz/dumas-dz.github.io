## 项目背景

CRM 对外服务需要面向合作伙伴和下游系统提供接口。除了业务正确性，还要解决访问来源控制、令牌管理、路径权限、限流、熔断和审计问题。如果各业务服务分别实现安全策略，会出现规则重复、鉴权口径不一致、故障扩散和维护成本高的问题。

项目目标是通过统一 Gateway 和 OAuth2.0 鉴权体系，把对外服务的入口安全和流量治理集中管理。

## 职责范围

我主导该模块开发，主要负责：

- 搭建 CRM 对外服务 Gateway 网关。
- 建设 OAuth2.0 鉴权服务，负责令牌管理与接口访问控制。
- 实现 IP 白名单、路径过滤和访问阈值控制。
- 集成 Sentinel 流控、熔断和降级机制。
- 接入 Nacos 服务注册发现与负载均衡。
- 参与对外接口的安全边界、错误响应和故障恢复设计。

## 技术方案

### 统一入口与多层防护

```text
外部请求
  -> IP 白名单
  -> Gateway 路径过滤
  -> OAuth2.0 / JWT 鉴权
  -> 服务路由与负载均衡
  -> Sentinel 流控 / 熔断 / 降级
  -> 业务服务
```

### 身份与访问控制

使用 OAuth2.0 组织令牌签发、校验和生命周期管理，结合 JWT 完成跨服务的身份传递。Gateway 统一负责路径过滤和访问阈值控制，业务服务只处理经过入口校验的业务请求。

### 流量治理

集成 Sentinel 对高频接口进行流控、熔断和降级配置，避免下游依赖异常持续放大为入口级故障。Nacos 提供服务注册发现，Gateway 负责按服务实例进行路由和负载均衡。

### 关键技术栈

`Spring Cloud Gateway`、`Spring Security OAuth2.0`、`JWT`、`Nacos`、`Sentinel`。

## 项目成果

- 搭建 OAuth2.0 鉴权服务及 Gateway 网关，形成统一对外入口。
- 实现令牌管理、IP 白名单、路径过滤和访问阈值等多层安全防护。
- 集成 Sentinel 流控、熔断和降级机制。
- 结合 Nacos 服务注册发现与负载均衡，提升系统的可靠性与可扩展性。

## 反思与改进

- **网关是安全边界，不是业务垃圾桶**：入口只处理认证、授权、路由、限流和审计，复杂业务校验应留在服务内部。
- **鉴权规则必须可审计**：令牌、调用方、路径、结果和异常需要有统一记录，方便追踪外部访问。
- **流控阈值来自压测和业务容量**：阈值不能只靠经验配置，应结合接口耗时、下游容量和失败率调整。
- **降级要有明确用户语义**：熔断后的提示、重试策略和兜底数据要提前设计，避免用户只看到模糊错误。
