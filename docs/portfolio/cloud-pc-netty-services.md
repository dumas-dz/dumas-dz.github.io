## 项目背景

云电脑和云手游服务需要同时支撑用户、商品订单、游戏、串流调度、运营活动和微信服务等多类业务。串流场景还涉及长连接、实时控制、房间互动和云算力节点接入，对连接管理、消息分发和服务扩展提出较高要求。

项目目标是把传统服务端拆分为可独立部署和扩展的微服务，并通过长连接和消息队列支撑多人游戏互动场景。

## 职责范围

我作为核心开发，负责：

- 负责云电脑服务端微服务架构设计。
- 参与用户、商品订单、游戏、串流调度和运营活动等核心服务开发。
- 搭建基于 Netty 长连接与 RocketMQ 的多路串流服务。
- 负责房间创建、邀请、键鼠控制等互动能力的服务端实现。
- 主导云手游及炮炮加速器服务端框架搭建。
- 对接 ARM 云算力平台与游戏加速节点服务。
- 负责运营活动、移动端推送和微信服务等模块。

## 技术方案

### 微服务拆分

按业务域拆分用户、商品订单、游戏、串流调度、运营活动和微信服务，使用 Spring Cloud Alibaba、Nacos、Sentinel、Dubbo 和 XXL-Job 组织服务注册、调用、治理和定时任务。服务之间通过明确接口和消息边界协作，避免把实时串流逻辑耦合进所有业务服务。

### Netty 长连接与 RocketMQ

```text
客户端 / 云算力节点
  -> Netty 长连接接入
  -> 连接与房间状态管理
  -> RocketMQ 消息分发
  -> 串流调度 / 游戏互动 / 控制指令
  -> 状态回传与异常恢复
```

Netty 负责高并发连接、消息编解码和实时控制，RocketMQ 负责异步消息分发和解耦。多路串流服务围绕房间创建、邀请、键鼠控制和状态同步组织，降低实时连接与业务模块之间的直接耦合。

### 云算力与游戏服务接入

对接 ARM 云算力平台和游戏加速节点，围绕资源分配、任务调度、节点状态和服务调用建立统一接入方式。运营活动、移动端推送和微信服务作为独立业务模块接入平台，避免影响串流主链路。

### 关键技术栈

`Spring Cloud Alibaba`、`Dubbo`、`Netty`、`RocketMQ`、`Nacos`、`Sentinel`、`XXL-Job`。

## 项目成果

- 完成云电脑服务端微服务架构设计，覆盖用户、商品订单、游戏、串流调度和运营活动等核心服务。
- 基于 Netty 长连接与 RocketMQ 搭建多路串流服务。

- 主导云手游及炮炮加速器服务端框架搭建，并对接 ARM 云算力平台与游戏加速节点。
- 完成运营活动、移动端推送和微信服务等模块的服务端开发。

## 反思与改进

- **实时链路和业务链路要分层**：连接、房间、控制指令与订单、活动、微信服务应使用不同边界，便于独立扩展和故障隔离。
- **长连接状态比普通接口复杂**：连接生命周期、心跳、重连、消息顺序和房间一致性都需要显式设计。
- **消息队列解决解耦，不解决所有问题**：需要同时设计幂等、重复消费、超时和积压处理。
- **云算力平台接入要抽象资源层**：不同节点的资源状态、调度策略和故障恢复应收敛到统一适配层。
