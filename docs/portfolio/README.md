## 内容说明

每篇案例统一采用以下结构：

1. **项目背景**：业务问题、系统边界和约束。
2. **职责范围**：个人负责或主导的模块。
3. **技术方案**：架构、关键设计和实现取舍。
4. **项目成果**：只保留简历已有或项目记录中的可验证成果。
5. **反思与改进**：从工程复盘角度总结可复用经验。

案例内容面向公开个人网站，不公开内部代码、密钥、客户隐私和电话等敏感信息。涉及公司业务时，使用“企业客服”“CRM 对外服务”等脱敏表述；公司名称仅用于说明工作经历来源。
