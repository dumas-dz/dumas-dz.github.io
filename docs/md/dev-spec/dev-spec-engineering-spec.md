# 工程规范与交付流程

## 1. 学习目标

- 把模糊需求转成带边界、验收标准和失败路径的开发任务。
- 组织小而完整的变更，让代码、测试、配置和文档在同一评审单元中交付。
- 为上线定义观察指标、灰度范围、回滚条件和责任人。
- 用复盘把一次故障或缺陷转化为测试、监控、流程或架构改进。

## 2. 适用场景

适用于功能开发、缺陷修复、数据迁移、依赖升级、接口变更和生产事故恢复。个人项目可以简化模板，但不能省略验收标准、测试证据和恢复路径。它不替代领域设计，也不规定具体 Git 分支模型。

## 3. 核心原则

### 3.1 可验证

需求必须能由产品、开发和测试用同一标准验收。“优化体验”不是验收标准；“列表首屏 P95 小于 800 ms，失败请求可重试且不重复扣款”才是可验证表达。

### 3.2 小步可逆

单次变更应保持主干可构建、可部署。高风险迁移先双写/影子读、再切流量、最后清理，避免一次性大爆炸。回滚不是备份旧包，而是验证数据兼容、配置恢复和业务补偿都可执行。

### 3.3 证据驱动

评审看差异和测试，发布看指标和日志，事故看时间线和因果链。结论必须能追溯到提交、运行结果、监控数据或用户反馈。

### 3.4 明确所有权

每个服务、接口、数据表、队列和告警都应有 owner、维护状态和升级路径。无人负责的共享组件会成为跨团队故障放大器。

## 4. 开发闭环

| 阶段 | 必须产出 | 常见检查 |
| --- | --- | --- |
| 澄清 | 背景、目标、非目标、验收标准 | 是否有错误路径、权限、容量和兼容要求 |
| 设计 | 方案、备选项、数据/接口变更 | 是否记录取舍、迁移和回滚 |
| 实现 | 代码、测试、配置、文档 | 是否保持小步、可构建、无敏感信息 |
| 验证 | 单元/集成/契约测试与静态检查 | 失败是否可复现，边界是否覆盖 |
| 发布 | 版本、灰度、指标、负责人 | 是否定义停止和回滚条件 |
| 复盘 | 结果、问题、改进项 | 是否转化为可跟踪的工程资产 |

## 5. 最小实践：完成一个可恢复变更

以“订单增加备注字段”为例，最小交付单元应同时包含数据库兼容变更、接口契约、写入/查询逻辑、测试、日志字段和发布说明。下面的检查表可直接放入任务描述：

```markdown
## 目标
订单创建和查询支持 200 字以内备注。

## 非目标
不修改历史订单 UI，不做富文本。

## 验收标准
1. 超长、空值、包含控制字符的输入有确定行为。
2. 新旧版本服务都能读写数据库，不因旧记录缺字段失败。
3. 创建、查询、审计日志覆盖 requestId 和 orderId。
4. 数据库、API 和权限变更可灰度并回滚。

## 交付证据
- 单元与集成测试结果
- 接口契约示例
- 灰度指标与回滚命令
- 数据兼容性说明
```

## 6. 代码与评审规范

- 命名表达业务意图；避免 `data2`、`handle1`、`TempUtils` 等无法解释职责的名称。
- 控制函数长度和嵌套深度，让主流程可扫描；复杂条件提取成可测试的判断。
- 失败处理必须明确：抛出、重试、降级、补偿或终止，禁止无提示吞异常。
- 对用户输入、外部响应、序列化数据和权限结果做边界校验。
- 评审优先讨论正确性、安全、兼容、可测试性和可运维性，再讨论风格。
- 依赖、配置、迁移、开关和密钥引用与代码一起评审；密钥本体不得提交仓库。

## 7. 发布与恢复检查表

- [ ] 版本可追溯到提交和构建产物。
- [ ] 数据库变更支持旧版本读取，且有备份/恢复验证。
- [ ] 灰度范围、观察指标、停止条件和回滚命令已演练。
- [ ] 超时、限流、重试、降级和幂等行为在测试中被验证。
- [ ] 日志、指标和告警能定位发布前后的行为差异。
- [ ] 值班人知道故障升级路径和业务补偿入口。
- [ ] 发布完成后核对 SLO、错误率、延迟、积压和成本。

## 8. 常见坑

1. **验收标准只写成功路径**：退款、超时、重复点击和权限不足时仍然失控。
2. **一次提交包含多个无关重构**：回归范围扩大，评审无法证明因果。
3. **数据库先删列/改类型**：旧版本实例仍在线时发生不可恢复错误。
4. **回滚只有“部署旧版本”**：新写入的数据或消息无法被旧代码处理。
5. **测试通过即发布**：没有容量、监控、灰度和业务指标证据。
6. **复盘只追责个人**：没有改进测试、设计、告警或流程，同类问题会重复。
7. **文档与实现漂移**：接口、配置和运行手册无人维护，事故时失去可信信息。

## 9. 总结与关联阅读

稳定交付来自可验收需求、小步变更、自动化验证、可观察发布和持续复盘。规范的目标不是增加流程，而是让风险更早暴露、让恢复动作更明确。
