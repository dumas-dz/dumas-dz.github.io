# 微服务治理

本主题关注跨团队、跨进程系统如何稳定交付：服务边界、RPC/事件契约、超时、流量、配置、发布和观测。

## 学习顺序

1. 阅读[微服务系统与治理](./arch-microservice-overview.md)。
2. 对一个服务画出同步/异步调用图，标注 timeout、幂等、重试、熔断和 owner。
3. 设计灰度、优雅下线、配置变更和依赖故障降级。
4. 结合[API 设计](../../dev-spec/dev-spec-api-design.md)与[日志规范](../../dev-spec/dev-spec-logging.md)补齐契约和排障证据。

## 检查表

- [ ] 拆分依据是业务边界与所有权，不是代码规模。
- [ ] 每条调用链有 deadline、重试预算、熔断、降级和追踪。
- [ ] 契约变更兼容，事件具备幂等和重放策略。
- [ ] 发布、回滚、配置、容量和故障升级都有演练。
