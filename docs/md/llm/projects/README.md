# AI 项目案例

> 内容状态：已完善  
> 最后审阅：2026-11-16  
> 适用范围：智能客服 Agent、Dify + MCP 工具平台、RAG 企业知识库及相关生产交付。

项目案例将前面领域的知识组合为可交付方案。每篇案例均按“业务问题 -> 范围 -> 架构 -> 数据与接口 -> 实施 -> 评测 -> 安全 -> 运维 -> 验收”组织，可直接裁剪为项目启动文档。

## 学习目标

- 将业务目标拆成能力边界、工作流、数据、接口和风险。
- 选择 Agent、Workflow、RAG、Dify 和 MCP 的合理组合，避免技术堆砌。
- 建立里程碑、质量门禁、上线灰度、成本和运营机制。
- 以可验证指标完成验收，而不是用 Demo 演示代替生产交付。

## 通用项目模板

### 1. 项目定义

```yaml
project:
  name: 示例 AI 应用
  business_owner: 业务负责人
  technical_owner: 技术负责人
  problem: 用一句话描述当前成本、风险或体验问题
  users: [用户角色]
  current_baseline: 当前处理时长/成功率/成本
  target:
    primary: 可量化业务目标
    guardrails: [严重错误, 安全, 成本, 时延]
  non_goals: [明确不做的场景]
```

### 2. 架构决策

- 为什么选择 Agent/Workflow/RAG/规则，而不是直接调用大模型？
- 哪些数据可进入模型，哪些只能通过业务工具查询？
- 哪些操作只读、可重试、需幂等、需二次确认、需人工审批？
- 模型、知识库、工具、Prompt 如何版本化和回滚？
- 失败时降级到规则、缓存、旧版本、人工还是转传统流程？

### 3. 交付物

| 阶段 | 必须交付 |
| --- | --- |
| 立项 | 问题定义、基线、范围、风险分级、预算 |
| 设计 | 架构图、数据流、接口、权限矩阵、威胁模型 |
| 开发 | 应用、编排、工具、数据管道、监控、审计 |
| 验证 | 功能、性能、安全、可靠性、评测和人工报告 |
| 上线 | 发布清单、灰度计划、回滚、运行手册、培训 |
| 运营 | 指标、成本、Bad Case、变更和复盘机制 |

### 4. 验收门禁

- [ ] 核心业务指标达到目标，基线和统计口径可复现。
- [ ] 安全高危样本零通过，权限和隐私检查有证据。
- [ ] P95/P99、成功率、队列、资源和成本不超过预算。
- [ ] 下游写操作幂等，重复请求、超时和断线不会产生重复副作用。
- [ ] 监控、告警、审计、运行手册和回滚经过演练。
- [ ] 评测数据、模型、Prompt、知识库和工具版本可追溯。
- [ ] 负责人、值班、升级路径和供应商支持已明确。
