# AI 评测与质量

> 内容状态：已完善  
> 最后审阅：2026-11-16  
> 适用范围：RAG、Agent、Workflow、结构化输出、对话与批量文本任务。

AI 评测不是一次性 Demo 演示，而是贯穿数据、开发、发布、线上运营的质量工程。它把“看起来不错”变成可比较、可回归、可归因的质量指标。

## 学习目标

- 建立覆盖效果、事实性、安全性、性能和成本的多维指标。
- 设计可版本管理的离线基准集，并建立上线门禁。
- 对 RAG 分开评估检索、生成和引用，对 Agent 分开评估规划、工具和结果。
- 使用在线反馈、抽样审核和影子流量持续修正离线指标。
- 防止数据泄漏、测试集过拟合和 LLM-as-a-Judge 偏差。

## 知识地图

| 层次 | 回答的问题 | 主要方法 |
| --- | --- | --- |
| 组件评测 | 模型、Embedding、检索、工具是否有效 | 单元测试、Recall/MRR、工具契约测试 |
| 端到端评测 | 用户任务是否完成 | 成功率、正确性、引用、完整性 |
| 在线评测 | 真实用户是否满意且风险可控 | A/B、采纳率、转人工、投诉、抽样审核 |
| 回归评测 | 变更是否破坏既有能力 | 分层基准集、发布门禁、趋势对比 |
| 运营评测 | 失败是否可聚类并闭环 | Bad Case 标注、错误分类、数据回流 |

## 核心原则

- **先定义任务成功，再定义指标**：不要用相似度替代业务成功。
- **评测集分层**：冒烟集、核心集、长尾/风险集、线上回流集分开管理。
- **组件归因**：RAG 答错时区分检索没找到、上下文没利用、生成事实错误。
- **评测版本化**：数据、提示、模型、知识库、评分器和代码都必须可追溯。
- **人机结合**：自动指标用于回归，高风险和争议样本必须人工复核。
- **禁止泄漏**：训练集、开发调参集、最终盲测集物理或逻辑隔离。

## 质量维度

| 维度 | 示例指标 | 典型权重 |
| --- | --- | --- |
| 任务结果 | 完成率、字段准确率、流程正确率 | 高 |
| 事实与依据 | 忠实度、引用命中、冲突处理 | 高 |
| 交互体验 | 相关性、完整性、简洁度、首字时延 | 中 |
| 鲁棒性 | 改写、噪声、缺信息、对抗输入 | 中 |
| 安全合规 | 注入成功率、越权率、PII 泄露率 | 一票否决 |
| 性能成本 | P95、成功率、Token、单位任务成本 | 中 |

## 发布前检查表

- [ ] 每个能力有任务定义、成功条件、黄金样本和明确失败分类。
- [ ] 数据集包含正常、边界、歧义、缺失信息和安全攻击样本。
- [ ] 评测脚本可重复运行，并输出逐样本结果和汇总 JSON。
- [ ] 核心集通过率不低于基线，安全集必须达到零高危通过。
- [ ] 对 LLM Judge 先校准，记录 Judge 模型版本、提示版本和抽样一致性。
- [ ] 对线上反馈设置标签规范、抽样比例、隐私权限和回流去标识化。
- [ ] 发布后监控业务指标、模型指标、性能指标和成本指标。
