# AI 工程化

> 内容状态：已完善  
> 最后审阅：2026-11-16  
> 适用范围：Python 3.11+、FastAPI 0.115+、Redis 7+、RabbitMQ/Kafka；Java 侧参考 Spring Boot 3、Spring WebFlux。

AI 工程化解决的不是“模型能不能回答”，而是“模型能力能否稳定地交付为业务服务”。本领域按照请求入口、异步任务、运行监控三个层次组织，覆盖 FastAPI、SSE、异步并发、重试、幂等、缓存、队列、持久化和可观测性。

## 学习目标

- 设计可流式、可重试、可恢复的 AI 对话与任务接口。
- 正确划分同步 API、异步队列和批处理任务的职责。
- 避免重复扣费、重复写库、消息丢失和长连接堆积。
- 用日志、指标、Trace 和业务事件定位模型、编排、检索、工具四类故障。
- 将功能验收转化为可自动执行的性能、稳定性和降级测试。

## 知识地图

| 主题 | 核心产出 | 关键检查 |
| --- | --- | --- |
| 服务接口 | 流式对话 API、任务受理 API | 超时、幂等、背压、错误协议 |
| 异步处理 | 队列 Worker、Outbox、事件日志 | 至少一次投递、去重、重放 |
| 数据与缓存 | 会话、结果、特征、限流数据 | TTL、失效策略、一致性 |
| 可观测性 | 指标、日志、Trace、业务事件 | Request ID 贯通、成本可归因 |
| 故障治理 | 重试、熔断、降级、限流 | 重试放大、依赖隔离、容量保护 |

## 端到端工程链路

```text
客户端
  -> API Gateway（认证、限流、请求大小限制）
  -> AI 服务（校验、幂等、缓存、Trace）
  -> Agent/RAG/Workflow
       -> 模型服务
       -> 向量库
       -> 业务工具/数据库
  -> SSE/HTTP 响应或队列任务
  -> 会话库、任务库、审计库、监控平台
```

## 上线前检查表

- [ ] 每个入口都有请求 ID、租户 ID、用户 ID、调用来源和成本标签。
- [ ] 写操作使用业务幂等键，不以请求体哈希替代业务去重。
- [ ] 模型、工具、数据库分别设置连接、读取、排队和总超时。
- [ ] 重试只覆盖瞬时故障，写操作重试必须幂等；限制并发重试。
- [ ] SSE 支持心跳、客户端断开取消、错误事件和有限缓存。
- [ ] 队列消费者采用至少一次语义，处理结果可重放但不会重复产生业务副作用。
- [ ] 建立 P95/P99 时延、Token、错误率、饱和度和单位任务成本指标。
- [ ] 降级方案经过演练：关闭联网、切换模型、返回检索摘要、转人工。

## 技术边界

- 单机内存缓存和内存幂等表只用于开发演示；生产环境使用 Redis 或数据库约束。
- “异步”不等于“非阻塞”：线程池阻塞调用、同步 SDK 和锁竞争仍会拖垮事件循环。
- SSE 适合单向文本流；双向音视频、复杂客户端协同优先考虑 WebSocket。
- 至少一次消息语义下，业务效果必须通过幂等键或状态机保证不重复。
