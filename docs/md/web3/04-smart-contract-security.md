# 智能合约安全

## 1. 学习目标

读完后能够为合约建立资产、角色、信任边界和失败模式清单，编写覆盖重入、权限、精度、授权和升级的测试，并知道何时需要外部审计。

## 2. 适用场景

适用于处理代币、资金、投票、签名授权、预言机数据、代理升级和跨链消息的合约。本文不是“审计工具清单”，而是开发前后的工程检查方法。

## 3. 前置知识

- 理解 Solidity 函数、事件、modifier、mapping 和调用上下文。
- 会写 Hardhat 测试，能构造恶意调用者和失败场景。
- 明确项目资产、管理员和外部依赖。

## 4. 核心概念

### 4.1 先写威胁模型

在代码前写出：

| 项目 | 必须回答 |
| --- | --- |
| 资产 | 什么会被盗、冻结或错误铸造？ |
| 角色 | 谁能暂停、升级、提款、改参数？ |
| 信任边界 | 哪些地址、RPC、预言机、桥和前端是外部输入？ |
| 失败模式 | 重入、价格操纵、抢跑、签名重放、DoS、精度丢失？ |
| 恢复 | 暂停、迁移、限额、时间锁和事故联系人是什么？ |

### 4.2 高频漏洞模式

- **重入**：外部调用返回前再次进入，使检查和状态写入不一致。遵循“先更新状态、再转出”，并使用 ReentrancyGuard；测试用恶意接收合约。
- **权限过宽**：owner、管理员、实现合约和升级代理都能改关键状态。采用最小权限、角色分离、时间锁和多签。
- **预言机/价格操纵**：单一现货价格、可预测区块值、低流动性报价都可能被操纵。使用多源、时间窗口、偏差阈值和延迟。
- **授权与签名重放**：无限授权、缺少 nonce/chainId/截止时间、签名域不明确。测试重复提交和跨链提交。
- **算术与精度**：Solidity 0.8 有溢出检查，但除法截断、单位换算、比例放大仍会出错。锁定精度约定并写边界测试。
- **DoS**：无界循环、回退接收者、单点依赖或必须按顺序处理的队列。设计批量上限和降级路径。
- **代理升级**：存储布局、初始化权限、实现合约自毁或恶意逻辑。尽量避免不必要的升级。

### 4.3 代码评审和测试分层

```text
单元测试：函数返回值、状态变化、事件、错误
属性测试：任意输入满足不变量，例如总供应量守恒
模糊测试：随机边界值、极大数组、异常地址
分叉测试：真实外部协议和价格依赖
对抗测试：重入、抢跑、签名重放、角色滥用
```

不变量示例：用户提款总额不超过存入总额；暂停后不能写入；代币总供应等于各账户余额之和；升级前后用户负债不被稀释。

## 5. 最小实践：写一个重入防护测试

先定义一个会重入的恶意接收者，再断言外部转账前状态已经更新：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

interface ITarget {
    function withdraw() external;
}

contract ReentrantAttacker {
    ITarget public target;
    bool private attacking;

    constructor(address target_) {
        target = ITarget(target_);
    }

    function attack() external {
        target.withdraw();
    }

    receive() external payable {
        if (!attacking) {
            attacking = true;
            target.withdraw();
        }
    }
}
```

测试不能只断言“攻击失败”，还要断言余额、事件、合约不变量和重试后状态。对真实资金合约，测试后还要做人工评审和外部审计。

## 6. 生产实践

- 代码仓库包含威胁模型、权限矩阵、部署参数、审计报告和已知限制。
- 部署后立即验证源码，锁定关键参数，监控角色变更、异常提款、价格偏差和暂停事件。
- 高价值权限使用多签 + 时间锁；管理员钱包与日常运营钱包分离。
- 上线前做测试网演练、事故演练和回滚沟通；不要把升级当作无成本修复。
- 对第三方库、代理、预言机和桥固定版本、来源和许可证，避免供应链漂移。

## 7. 常见坑

- 认为“合约开源 = 安全”，忽略运行时依赖和管理员权限。
- 只测成功路径，不测攻击者、失败回退和并发调用。
- 用单个价格源或 `block.timestamp` 做关键业务判定。
- 把前端校验当作链上校验；任何人都能直接调用合约。
- 事故发生后把助记词、私钥或签名放进工单和聊天记录。

## 8. 练习

1. 为一个提款函数写检查-状态-交互顺序错误，然后修复并保留攻击测试。
2. 列出一个合约的三个特权角色，定义各自最小权限和撤销流程。
3. 用 Foundry fuzz 或 Hardhat fast-check 测试余额守恒不变量。
4. 编写事故响应表：发现异常、暂停、取证、公开沟通、恢复分别谁负责。
