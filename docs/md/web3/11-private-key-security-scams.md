# 私钥安全与常见骗局

## 1. 学习目标

读完后能够设计钱包备份、密钥分层、授权审查、签名确认和事故响应流程，识别常见钓鱼模式，并知道何时撤销、迁移和公开沟通。

## 2. 适用场景

适用于个人学习钱包、DApp 开发、团队运营、开源 Demo 和公开教程。本文不提供任何真实助记词或私钥；示例只使用 `<MNEMONIC>`、`<PRIVATE_KEY>` 等不可用占位符。

## 3. 前置知识

- 理解 EOA、消息签名、交易、授权和测试网。
- 会使用密码管理器、Git 和命令行。
- 了解“公开地址可以展示，秘密材料不可以展示”。

## 4. 核心概念

### 4.1 秘密材料分层

| 材料 | 可见性 | 保护方式 |
| --- | --- | --- |
| 地址/公钥 | 可公开展示 | 检查来源和网络 |
| 签名 | 根据用途决定公开 | 只签明确意图，记录过期和域 |
| 私钥/助记词 | 永不公开 | 离线、加密备份、硬件钱包 |
| 部署密钥/CI secret | 仅受控环境 | secret manager、最小权限、轮换 |

助记词不是登录密码，私钥不是 API Key。不要把它们写入源码、截图、Issue、日志、测试夹具或聊天工具。写入 `<PRIVATE_KEY>` 占位符的文档也只能说明注入方式，不能替代真实 secret 管理。

### 4.2 常见骗局

- **假钱包/假客服**：要求“验证钱包”、导出助记词、远程控制或安装未知扩展。
- **钓鱼签名**：伪装成领取空投、授权验证、升级合约，诱导盲签或无限授权。
- **假域名/相似地址**：使用 Unicode 相似字符、短链、搜索广告和伪造浏览器书签。
- **恶意合约/代币**：转账税、黑名单、可升级后盗取授权、伪造 NFT 元数据。
- **招聘/开源供应链**：要求运行含 secret 的脚本，或在 CI 中读取环境变量并外发。
- **假交易截图**：仅凭截图、私聊链接或“客服确认”不能证明链上事实。

### 4.3 授权和签名检查

签名前逐项确认：域名是否正确、目标网络是否正确、方法和参数是什么、spender 是谁、额度和过期是什么、是否需要无限授权。对授权定期撤销，优先使用精确额度；交易成功后以 receipt 和浏览器链上数据复核。

## 5. 最小实践：建一份个人钱包检查表

在本地 Markdown 或密码管理器的安全备注中完成：

```text
[ ] 助记词离线备份，至少两个受控位置
[ ] 私钥和助记词不进入 Git、截图、聊天和浏览器同步
[ ] 学习钱包、开发钱包、运营钱包分层
[ ] 高价值操作使用硬件钱包或多签
[ ] 记录常用域名、chain ID、合约地址和 ABI 来源
[ ] 定期撤销不需要的授权
[ ] 演练一次误签、误授权和 RPC 失败的恢复步骤
```

不要把清单填入真实秘密；只记录“已使用何种保护、何时检查、联系人角色”。

### 5.1 事故响应

发现异常时按固定顺序处理：

1. 停止继续签名和操作，保存 txHash、地址、时间、网络和界面截图（不含秘密）。
2. 从独立设备和独立 RPC 查询链上状态，区分只是前端假象还是资产/权限已变化。
3. 若私钥可能泄露，使用安全设备迁移到新钱包；若只是授权过宽，撤销授权并暂停相关合约。
4. 轮换 CI/部署密钥，检查仓库历史、依赖和浏览器扩展。
5. 向用户/团队说明影响范围、已完成动作、待办和恢复条件；不要传播助记词来“共同排查”。

## 6. 生产实践

- 开发和生产使用不同钱包、不同 RPC、不同 secret；CI 只注入短期密钥。
- 对签名请求实现域绑定、nonce、过期、最小权限和审计日志。
- 前端显示完整地址、合约来源、方法、网络、费用和授权额度，支持复制和浏览器复核。
- 团队执行密钥轮换、离职回收、权限复核和事故演练；高价值操作采用多签与时间锁。
- 依赖锁定、代码签名、浏览器扩展白名单和发布产物哈希，降低供应链风险。

## 7. 常见坑

- 把助记词输入“客服验证”“领取奖励”或未知网页。
- 为了方便保存无限授权，忘记后续撤销和 spender 变化。
- 只信浏览器余额和截图，不查看交易 receipt、合约代码和网络。
- 事故后继续使用同一浏览器、同一设备或同一私钥排查。
- 在教程中粘贴看似随机但实际可用的私钥、助记词或 Keystore。

## 8. 练习

1. 编写一份签名确认组件，展示 domain、chain ID、方法、参数、额度和过期。
2. 模拟一次无限授权，执行撤销并记录授权前后状态。
3. 设计误签事故演练：谁停止操作、谁取证、谁迁移、谁沟通。
4. 检查一个仓库，列出不应出现的秘密位置和 CI 注入改进点。

## 9. 总结与关联阅读

安全的第一原则是控制秘密材料和最小权限；技术工具只能降低风险，不能替代谨慎操作。继续阅读 [账户与交易模型](./01-web3-account-model.md)、[智能合约安全](./04-smart-contract-security.md) 和 [测试网部署](./10-testnet-deployment.md)。
